# G17 pressure-aware virtual scheduling

Status: promoted through normal scalar allocation; final integration gates recorded below.

The gap is avoidable spills caused by allocating all independent definitions
before their consumers. `baseline-spill.py` freezes the validated group and
predicate allocator. `baseline.json` records six valid workloads requiring
18/74/77/85/19/29 word slots, with 80/304/320/352/80/160-byte frames.

`pressure.py` builds a virtual dependency DAG with RAW, WAR, WAW and predicate
guards, retains load order and fixed store/synchronization/control boundaries,
and selects ready operations by live scalar/group/predicate pressure. Starting
an incomplete pair/quad receives a scheduling penalty so many address copies
cannot cheaply displace their wider consumers. It never changes operations,
expressions, predicates or encoding fields. The first, weaker group heuristic
is retained in `first-pressure.py` and `candidate-offline-first.json`.

`spill.py` is generated by `candidate.py`. Ordinary successful allocation stays
unchanged. A replacement for a spilled plan must use strictly fewer slots, no
larger frame, and no more local loads/stores in any corresponding basic block.
An earlier resource rejection can be recovered by a successful scheduled plan.
Both allocation plans can require host compile work; this is not a compile-time
speed claim. Slot reuse, tensor-fragment pressure and occupancy policy remain
separate work.

`candidate-offline.json` passes all 24 normal/poisoned full-output configurations
with independent integer references and guards. The six new workloads use zero
spill slots; the declared-local loop still reserves its own 32 bytes.
`candidate-controls.json` checks all seventeen kernels with independent pairwise
order constraints, fixed boundaries, exact operation identities, corruption
rejection, actual allocations and per-block local transfer counts. All eleven
legacy pressure kernels keep their original allocations exactly.

`run_modal.py` compares frozen OA, candidate OA and same-PTX ptxas at all four
levels. It checks complete input/output/guard/tail bytes before collecting 21
resident CUDA-event samples per opt variant, in randomized paired order. Raw
bytes are stored once by SHA-256 and referenced by every launch; deduplication
does not replace complete-byte verification. `audit.py` independently rebuilds
each native kernel and rechecks full bytes, resources, ownership, sample order
and medians. No result counts as passed before the report/archive are returned
and this audit succeeds.

Four separate frozen-pass controls vary limits/counts and add exact finite FP32
FMA. They are parameter/arithmetic controls, not a held-out application
distribution. `heldout-freeze.json` binds the unchanged algorithm. The first
float source used decimal literals that the existing parser rejected; its
source, freeze and failed offline report/log remain retained. The final source
uses admitted raw-bit literals. The finite integer/half-integer FP32 trajectory
is exactly representable and has an independent integer-derived reference;
this does not prove arbitrary IEEE edge cases. Its final sixteen offline
configurations pass without spills.

Production promotion requires completed A100 byte/native/resource/timing
audits, normal compiler regressions, policy/application continuity, full suites
and the canonical [spilling dossier](../../../docs/compiler/gaps-spilling.md).
The original 51-gap program remains incomplete.

The initial `candidate-audit.json` is a numerical/executable rehearsal. Its
auditor source file changed while that process ran, and its return-time source
hash cannot establish the executing auditor identity. The explicit
`candidate-audit-custody.json` excludes it from promotion authority. Stable
production audits independently repeat every complete-byte/native/resource/
timing check; hardware reports and archives stay unchanged.

The final admission additionally recognizes all control-flow terminators when
checking transfer counts. `hardware-spill.py` retains the exact prototype used
in paired runs; `terminator-repair.json` proves the single-line admission change.
`final-a100-20261123T112918Z.json` admits the final bytes with 128 launches,
including a guarded early return and recovery of a maximum local frame that
the baseline rejected. Independent audits regenerate every prototype binary
with the final allocator; historical hardware reports are never rewritten.

The main run passes 1,632 correctness, 1,071 timed and 153 warmup launches.
The separate controls pass 384 correctness, 252 timed and 36 warmup launches.
Both use A100-SXM4-40GB, driver 13030, Python 3.12.1 and toolkit 12.8.1.
No report counts as integrated until its read-only production audit passes.
The three stable production audits pass 627,347,456 complete retained bytes
and 176 native comparisons, with exact sources, ownership, frames, register
resources, timing sample order and recomputed medians.

`compile-cost.json` records a separate warm-encoder host code-generation
comparison: median scalar96 baseline/candidate 2.574/2.661 seconds, pred24
0.238/0.254 seconds, and legacy group4_auto 9.761/25.510 seconds. The latter
retains the same executable. This constructed measurement excludes parsing,
toolkit/packaging and GPU work, uses three samples, and does not control all
concurrent host work. It exposes additional compilation cost without claiming
a complete application break-even result. A separate instrumented scheduler
profile is retained; its elapsed time is not an uninstrumented timing sample.

Full integration passes 2,927 supported-environment tests and 2,442 tests with
15 explicit skips in the separate compiler-only environment. The normal
production regression file has 29 tests. Current policy continuity preserves
49 measured policies across 98 retained sessions; application continuity
preserves 1,386 earlier native kernel occurrences. `validation.json` binds the
final source, evidence, suite and documentation identities. Broad G17 remains
partial under its original exit gate.
