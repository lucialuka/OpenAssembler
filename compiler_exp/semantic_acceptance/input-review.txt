**Assessment:** OpenAssembler is a bounded SM80 compiler with a typed Python kernel language and a small exact-shape model compiler. It is far from arbitrary Python/CUDA/PTX coverage. There are both missing semantics and accepted PTX forms that produce incorrect native results. More exact GEMM tuning does not close these compatibility gaps.

## Priority correctness defects

### P1: integer saturation is silently discarded

`add.sat.s32` and `sub.sat.s32` reach the ordinary integer selector, which emits `IADD3` without saturation and without rejecting `.sat`. See [openassembler/backend/ra.py](/Users/lucasfang/Desktop/OpenAssembler/openassembler/backend/ra.py:675).

| Contract | Correct signed result / ptxas | OA on A100 |
|---|---:|---:|
| `INT_MAX + 1`, signed saturating add | 2147483647 | -2147483648 |
| `INT_MIN + (-1)`, signed saturating add | -2147483648 | 2147483647 |
| `INT_MAX - (-1)`, signed saturating sub | 2147483647 | -2147483648 |
| `INT_MIN - 1`, signed saturating sub | -2147483648 | 2147483647 |

Both independent CPU interpretation and same-source ptxas hardware agree with the expected saturated value. OA-native executable words were checked against the cubin before launch. All four failures reproduce for three poison patterns; a nonoverflowing saturating-add control passes. This is a compiler correctness defect, not merely unsupported coverage.

### P1: floating predicate flush-to-zero is silently discarded

`setp.ftz.eq.f32` reaches `setp()`, which emits `FSETP.EQ.AND` without `.FTZ`. See [openassembler/backend/ra.py](/Users/lucasfang/Desktop/OpenAssembler/openassembler/backend/ra.py:537). Positive and negative minimum FP32 subnormals should compare equal to zero under this contract. Same-source ptxas returns 1; OA returns 0, for both signs and all poison patterns. The corresponding comparison without `.ftz` correctly returns 0.

**Consequence:** the frontend/parser/backend acceptance ledger needs to track complete opcode + modifier + type + operand + memory/synchronization contracts. Mnemonic support, parser acceptance and valid instruction encoding do not by themselves establish semantic support. Unsupported modifiers must either receive faithful lowering or a hard rejection. Full build packaging does not repair an incorrect encoded instruction sequence. This review leaves both defects unchanged, as requested.

### P2: CLI color detection can retain a closed stdout object

[supports_color](/Users/lucasfang/Desktop/OpenAssembler/openassembler/ui/colors.py:13) binds `sys.stdout` as a default argument at import time. Importing it under a temporary redirected stdout, closing that stream and calling it afterward raises `ValueError: I/O operation on closed file`. A fresh-process standard-library reproducer confirms this independently of pytest; see [closed-stream-reproducer.json](closed-stream-reproducer.json). The two pinned full-suite welcome failures hit the same line. This is a CLI embedding/capture robustness issue, separate from GPU capability coverage.

Precision is itself a coverage boundary. The model plan excludes NaN/Inf and overflowing intermediates. Its half-rounded product mode declares a straight-through input cast and independent operand rounding in backward products; that is a separate contract from strict FP32 or generic AMP. The Python kernel language also uses approximate exp/log/tanh/rsqrt intrinsics and fixed-width numerical semantics. Comparators need those exact policies, not a shared dtype label alone. See [declared numerical domain](/Users/lucasfang/Desktop/OpenAssembler/openassembler/modelfront/graph.py:180).

## What changed since the earlier review

The older bare/weak-entry and launch-header omission findings should not be presented as current defects: they were repaired. Current source also has broader inference discovery, half-rounded BMM/attention recipes and two more admitted exact GEMM routes. These remain bounded features. Native composed attention is unmasked; fused/causal/masked attention is outside that contract.

The previous statement that model reports have no compile-phase breakdown is now too broad. [The worker](/Users/lucasfang/Desktop/OpenAssembler/openassembler/modelfront/worker.py:322) reports CPU factory, capture/autodiff, storage planning and native bundle/weights time. It still combines PTX emission, backend generation, ptxas, packaging, disassembly and cache validation within aggregate bundle work. Per-kernel GPU timing distributions and a complete queue/startup/transfer/archive timeline remain absent from the standard report. `host_step_ms`, stream elapsed samples, launch ledgers, profiler audits and zero-vendor-compute reporting are useful existing pieces.

Historical performance evidence must keep comparator meanings separate. The retained 42-contract campaign reports OA slower than same-PTX ptxas in every nominal-selected comparison, despite improving OA's own baseline. Its ptxas ratios concern nominal selections, which can differ from the frozen installed policy. cuBLAS results used a particular GemmEx call, not exhaustive cuBLASLt tuning. Earlier Triton/Inductor/eager results and the two newer exact-policy admissions have different contracts/devices and do not establish a current universal speed claim. See [comparison scope](/Users/lucasfang/Desktop/OpenAssembler/exp/dispatch_tuning/RESULTS.md:67) and [new admissions](/Users/lucasfang/Desktop/OpenAssembler/docs/compiler/memory-latency.md:89).

For the full requested report contract, remaining work includes standardized stage timers, per-kernel randomized raw samples, resource/launch/fusion accounting, exact model-wide comparator semantics, correctness gates before timing and compile amortization `build + startup + N * steady_state`. Unsupported rows must stay outside performance aggregates. No failed candidate in this review was timed.

## Test coverage is not capability coverage

| Probe family | Cases | Accepted at stated stage | Unsupported | Incorrect |
|---|---:|---:|---:|---:|
| ptx | 32 | 4 | 26 | 2 |
| target | 2 | 0 | 2 | 0 |

| python | 10 | 2 | 8 | 0 |

The hand-picked set deliberately stresses missing features. There is no defensible percentage of arbitrary Python, CUDA or PTX coverage from these counts: that needs a declared language/version/architecture domain and an independently chosen workload corpus. A thousand passing regression tests can coexist with an unsupported basic operator and a missed modifier-semantic defect. Passing CPU graph algebra also does not establish full-output, gradient, optimizer-state or performance equivalence on a GPU.

There is a distribution/evidence gap as well: `.gitignore` excludes `compiler_exp/` and `docs/compiler/research-plan.md`, even though maintained docs link to them. The live working-tree doc checker passes 149 Markdown files, but the Git-based review snapshot fails 17 link/directory checks. Sixteen point to those omitted paths; one points to an omitted historical `runs/` directory. This separates locally retained evidence from what Git/Homebrew source archives can reproduce. See [.gitignore](/Users/lucasfang/Desktop/OpenAssembler/.gitignore:64) and the two documentation logs. This is separate from native ISA coverage.

## Suggested order for closing the gap

1. **Make acceptance semantically reliable.** Fix or reject saturation and predicate FTZ; inventory complete modifier/type/operand contracts and retain independent NVIDIA acceptance controls and A100 tests. Keep unsupported, invalid, failed and unverified distinct.
2. **Complete a declared device target.** Prioritize SM80 atomics/order, device calls/linkage, local memory/spilling, parameter ABI and missing scalar/tensor types/forms. Test kernels emitted by nvcc from independent CUDA/CUTLASS-style inputs, not just OA-generated PTX.
3. **Make real applications executable.** Resolve original build/dependency/extension/launch contracts and preserve CPU host work. Extend normalized framework operators, layouts/broadcasting, dtypes, RNG/effects, dynamic guards, losses and optimizer state. Add independent CNN/transformer/custom-extension applications with full state and checkpoint gates.
4. **Generalize efficiency after correctness.** Add shape/layout coverage, fallback lowerings, fusion/packing/launch planning and measured scheduling/cost models. Compare exact PTX against ptxas, complete models against Triton/Inductor/eager and matching GEMMs against explicitly tuned/untuned libraries. Keep GPU variants and toolkit environments separate.
5. **Expand architecture and toolchain independence explicitly.** New encoders/ABIs/resource models need their own conformance and hardware evidence. An independent cubin/linker path is a different milestone from OA ownership of replaced kernel text.

“Everything” needs a precise boundary: all valid device kernels for declared targets and language semantics is a concrete conformance goal. Arbitrary Python host objects, I/O and dependency execution also need a CPU/runtime contract. Unknown generated code needs an explicit runtime specialization policy. Semantic completeness and efficient output across workloads need separate acceptance criteria; universal speed superiority cannot follow from source acceptance.
